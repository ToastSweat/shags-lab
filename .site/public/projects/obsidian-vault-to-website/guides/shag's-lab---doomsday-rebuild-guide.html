Shag’s Lab: The Doomsday Rebuild Guide

This is the file for Future Me, Curious You, or Whoever Is Looking At A Dead PC Wondering Why A Personal Wiki Needed A Build Pipeline.

The short version:

The Obsidian vault is the source of truth.

Everything else is replaceable.

The live site is a static Quartz build made from explicitly public notes in that vault. The vault and generated site live in one private Git repository. The home PC builds and pushes it. The web host pulls it and copies only the finished public files into Apache’s web root.

If every piece of software involved in this project vanished tomorrow, the important part would still be a folder full of Markdown files and images.

That is the point.

Normal publishing workflow

On the home PC:

  1. Work normally in Obsidian.
  2. Add/update notes.
  3. Set publish: true only on things that should be public.
  4. Run Publish-ShagsLab-HomePC.bat.

That BAT runs the PowerShell publisher.

The publisher:

  1. Scans the vault.
  2. Generates Updates Home.
  3. Generates Projects Home.
  4. Creates a clean Quartz staging directory.
  5. Copies only published notes.
  6. Copies assets referenced by published notes.
  7. Turns Welcome.md into index.md.
  8. Builds Quartz.
  9. Mirrors the built static site into .site\public inside the vault repository.
  10. Commits the vault and generated site.
  11. Pushes main to GitHub.

Then, on the web host, run:

That:

  1. Pulls origin/main.
  2. Verifies .site\public\index.html exists.
  3. Mirrors .site\public into C:\xampp\htdocs\helvete\lab.

Done.

Windows PowerShell throws bizarre parse errors around normal code

The publisher must remain safe for Windows PowerShell 5.1.

The original failure came from a Unicode em dash in a UTF-8-without-BOM .ps1, which PowerShell misread and then produced a cascade of nonsense parser errors.

Keep the operational publisher script ASCII-only unless PowerShell encoding behavior is deliberately changed.

The actual backup philosophy

There are several layers here and they have different jobs:

The most important data is always:

If the website disappears, rebuild it.

If Apache disappears, rebuild it.

If Quartz disappears, replace it with something else.

Do not contort the vault around the website.

The website exists to present the vault.

The vault does not exist to feed the website.

Final sanity checklist

When everything is healthy:

  • F:\[DIARY]\Shag's Lab opens normally in Obsidian.
  • git status in the vault is clean after publishing.
  • The private GitHub repo has the newest commit.
  • .site\public\index.html exists in the repo.
  • C:\PGN\ShagsLab exists on the web host.
  • C:\xampp\htdocs\helvete\lab\index.html exists.
  • https://helvete.pizza/lab/ loads without a certificate warning.
  • win-acme shows healthy scheduled renewals.
  • Updates Home and Projects Home are being generated instead of maintained by hand.

If all of that is true:

Leave it alone.

It works.

Go make another weird thing.
