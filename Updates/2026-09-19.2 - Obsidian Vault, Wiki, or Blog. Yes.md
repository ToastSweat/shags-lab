Obsidian Vault, Wiki, or Blog? Yes.

I work on too much weird shit.

That is not a complaint.

The problem is that I finish something, move on to the next thing, and six months later I vaguely remember that I once spent three nights teaching a keyboard to type `‰` or stood up a game server or wrote some little utility that absolutely nobody asked for.

I wanted somewhere to keep all of that.

Discord felt too temporary and too closed off. Facebook, Twitter, YouTube, etc. sounded like turning my hobbies into Content™, which is not what I wanted either. A normal blog was closer, but I kept getting hung up on the same thing:

What happens when the blog platform goes away?

I don't want my diary to belong to a website.

That was the useful realization.

The website should just be a **view of the diary**.

So I made an Obsidian vault called:

```
Shag's Lab
```

The actual vault lives on my PC at:

```
F:\[DIARY]\Shag's Lab
```

And the whole idea is basically summed up by the welcome page:

> This is part blog, part wiki. All me.

There are really only two important concepts.

`Updates` are moments in time.

`Projects` are persistent things.

Updates are the chronological "here is what I have been doing" side of it. Projects are the "tell me everything about this particular rabbit hole" side.

A project gets its own folder, a Home note, Guides, Assets, whatever else it actually needs.

An update gets stupidly simple metadata:

```yaml
---
type: update
date: 2026-09-19
project: Obsidian Vault to Website
publish: true
---
```

Project Home pages work similarly:

```yaml
---
type: project
project: Obsidian Vault to Website
status: active
publish: true
---
```

The important property is:

```
publish: true
```

My vault can contain whatever I want.

The public website only gets the things I deliberately mark public.

That part mattered a lot.

Then I put the whole vault under Git.

Not the website.

The **actual diary**.

Every Markdown file, every guide, every project note, every original screenshot.

Now even if I rewrite a page five years from now, Git still has the old version.

That alone made this worth doing.

The next piece was Quartz.

Quartz takes Markdown and turns it into a static website, which is almost exactly what I wanted. I keep writing normal Obsidian notes and Quartz makes browser food out of them.

Of course it was not quite as simple as:

```
npm install happiness
```

There were a few adventures.

The folder name `[DIARY]` taught PowerShell that brackets are apparently exciting, so paths like this:

```powershell
cd "F:\[DIARY]\Shag's Lab"
```

did not work the way I expected.

The answer was:

```powershell
Set-Location -LiteralPath "F:\[DIARY]\Shag's Lab"
```

Then Quartz installed its default theme without actually installing its default theme.

So this:

```
Cannot find module '@quartz-themes/default'
```

was solved with:

```powershell
npm install @quartz-themes/default
```

Then the homepage was called `index`.

Then it was a 404.

Then the Explorer was empty.

Then the graph was one lonely purple dot.

All completely reasonable once I realized Quartz had only been given one file.

Eventually I stopped manually copying things around and wrote a publisher.

That is where the setup became actually useful.

My normal source remains:

```
F:\[DIARY]\Shag's Lab
```

Quartz itself lives separately at:

```
F:\[DIARY]\ShagsLab-Web
```

The publisher scans the vault, regenerates `Updates Home` and `Projects Home`, collects only notes with `publish: true`, grabs the assets those notes actually use, maps `Welcome.md` to the website homepage, and feeds that sanitized copy to Quartz.

Then Quartz builds the finished static site.

The finished site is copied back into the same Git repository under:

```
.site\public
```

So there is only **one repository**.

Thank Christ.

The private GitHub repository contains both my permanent vault and a generated copy of the public website.

That also gives me an off-machine backup.

The web server is another Windows PC entirely.

It pulls the same private repo into:

```
C:\PGN\ShagsLab
```

Then a tiny BAT file copies only:

```
C:\PGN\ShagsLab\.site\public
```

into Apache's actual public directory:

```
C:\xampp\htdocs\helvete\lab
```

That separation means the server can have the full private repo checked out without Apache exposing the vault itself.

Only the generated public site gets copied into the web root.

So publishing now looks like this:

```text
HOME PC

Obsidian
   ↓
Publish-ShagsLab-HomePC.bat
   ↓
generate indexes
   ↓
filter public notes
   ↓
build Quartz
   ↓
.site\public
   ↓
Git commit + push
   ↓
GitHub


WEB HOST

Git pull
   ↓
.site\public
   ↓
C:\xampp\htdocs\helvete\lab
   ↓
Internet
```

That is exactly the level of boring I wanted.

Naturally, the very last boss fight was SSL.

The certificate for `helvete.pizza` had expired and the old win-acme renewal had apparently been failing for a while.

It had:

```
247 errors
```

Cool.

Trying to renew it hit an ACME ARI `replaces` error, so I created a fresh certificate instead, used HTTP validation against the existing Apache root, exported new PEM files straight into Apache's certificate directory, restarted Apache, and cleaned out the dead renewal.

Finally:

[https://helvete.pizza/lab/](https://helvete.pizza/lab/)

Shag's Lab is live.

It is not really a blog.

It is not really a wiki.

It is not really a portfolio.

It is my project diary, and the website is just one way of looking at it.

If the website dies, I still have the vault.

If Quartz dies, I still have the vault.

If I redesign the whole thing later, I still have the vault.

If my PC dies, GitHub has the vault.

And if Future Me is staring at the smoking remains of all of this wondering what the hell Past Me did, I made him a [[Shag's Lab - Doomsday Rebuild Guide]].

You're welcome, asshole.
