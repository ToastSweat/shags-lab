I have been slowly turning Shag's Lab from "a folder full of Markdown files that happens to become a website" into an actual little publishing system.

Today I finally crossed another thing off the list: **automatic publishing and Discord announcements.**

The basic idea is pretty simple now.

Every night, my main PC can:

- validate the vault metadata
- generate the Updates and Projects pages
- build the Quartz website
- commit everything
- push the finished site to GitHub

Then the dedicated server can wake up later, pull the newest version, deploy it to Apache, and check whether any new Updates were published.

If there are new posts, it sends **one Discord message** containing all of them.

So if I write three updates during the day, Discord does not get spammed three separate times. The next deploy sees all three and bundles them into one announcement.

It also keeps track of what it has already announced, so running the deploy script again should not post the same thing twice.

That part was important.

We initialized the system today with **73 existing Updates** and deliberately marked those as the baseline so Discord did not suddenly get blasted with the entire history of Shag's Lab.

I also finally cleaned up something that has been bugging me in the metadata.

Updates can now properly belong to multiple projects using YAML lists:

```yaml
project:
  - Project One
  - Project Two
```

instead of trying to cram multiple project names into one comma-separated string.

The publisher understands both single-project posts and project lists, validates the names against real project/project-parent pages, and carries that information all the way through to the deployment manifest used by Discord.

This post is actually the first real end-to-end test of the whole thing.

If everything works:

1. I save this note.
2. The home PC publishes Shag's Lab.
3. The dedicated server deploys it.
4. Discord sees exactly one new Update.
5. This post appears in the announcement.
6. Running the deploy again does absolutely nothing.

Which is exactly the kind of boring automation I love.

If I never have to manually copy a website update or paste a new-post link into Discord again, this was worth it.
