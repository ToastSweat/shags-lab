# I Put a Binary Clock on My Monitor

Apparently a normal clock was not nerdy enough.

I have a CORSAIR XENEON EDGE sitting on my desk, and once I realized iCUE supports custom widgets, there was really only one reasonable thing to do:

Make the time harder to read.

So I built **Atomic Binary Clock**, a native iCUE widget that displays the time as square binary blocks.

[GitHub: ToastSweat/icue-binary-clock](https://github.com/ToastSweat/icue-binary-clock)

The design is intentionally simple: lit squares, outlined unlit squares, no rounded corners, no animation, and a purple default palette meant to look at home next to my Atomic Purple display.

Because if I am going to make a clock that requires math, it should at least look good doing it.

## There are two ways to make time unnecessarily complicated

The clock supports two binary modes.

The default is **BCD**, or binary-coded decimal.

Instead of treating `23:59:47` as three numbers, it treats it as six separate digits:

```text
2 3 : 5 9 : 4 7
```

Each digit gets four bits with weights:

```text
8
4
2
1
```

Add the lit squares and you get the digit.

For example, a `7` is:

```text
4 + 2 + 1
```

Very practical.

Very normal.

The other mode represents the whole hour, minute, or second as a six-bit value:

```text
32
16
8
4
2
1
```

So instead of six digit columns, I get one binary value for hours, one for minutes, and one for seconds.

I also added optional bit-weight labels, because there is a limit to how long I am willing to stare at glowing purple squares pretending I immediately know what time it is.

## It actually behaves like a real iCUE widget

This was not just a little HTML clock shoved onto the screen.

The widget uses iCUE's native settings system, so I can change things directly from the XENEON EDGE widget controls:

- BCD or whole-value binary;
- 12- or 24-hour time;
- local time or UTC;
- seconds on or off;
- numeric time and labels;
- bit weights;
- text, lit-square, unlit-square, and background colors;
- block size and spacing;
- lit-block brightness;
- widget transparency.

The master **Show text** switch hides the title, labels, numeric time, AM/PM, and bit weights together.

The useful part is that the layout does not just leave a bunch of dead space afterward.

When the text disappears, the squares automatically grow into the space that was freed up.

Turn the text back on and the individual text settings are still there.

That sounds like a tiny detail until you remember this thing has to work across a pile of completely different widget dimensions.

## Landscape. Portrait. Tiny. Huge.

The XENEON EDGE supports several widget slot sizes in both landscape and portrait orientations.

The clock handles all eight of them.

On wide layouts, the binary groups sit in the more obvious clock-like arrangement.

On tall portrait layouts, the groups stack and the bit columns become horizontal rows instead.

So instead of reading bit weights from top to bottom, portrait mode reads them left to right.

The important part is that the blocks stay square.

Not approximately square.

Not "close enough if nobody looks too hard."

Square.

I apparently care about this.

## Transparency became its own little project

Version 1.1.2 added support for iCUE's standard widget transparency property.

The page itself stays transparent while a separate background layer gets faded, which means the transparency slider does **not** wash out the clock blocks, text, or outlines.

That also keeps the independent lit-block brightness setting separate from background transparency.

I made a checkerboard test fixture to verify the behavior at fully transparent, partially transparent, and opaque settings, then used screenshot pixel checks to make sure the background changed while the lit squares did not.

Completely reasonable amount of testing for a clock.

One caveat remains: previous versions of the clock work on the physical XENEON EDGE, and the new 1.1.2 transparency behavior is verified in the browser simulator using the same value mapping as CORSAIR's built-in clocks.

I still need to confirm the actual page-personalization transparency slider on the hardware after importing 1.1.2.

So that part is **tested, not yet physically confirmed**.

## No companion app. No server. No nonsense.

Unlike some of my other XENEON EDGE experiments, this one does not need anything running in the background.

No local server.

No API key.

No account.

No network calls.

No extra plugin.

No little Python process quietly living in the system tray.

It is just the widget.

The clock reads the PC's real wall time every second and uses either the system's local timezone and daylight-saving rules or UTC.

That also means sleep, clock corrections, and other interruptions do not slowly introduce drift.

The computer already knows what time it is.

I decided not to reinvent that particular wheel.

## I may have tested it a little

The project has automated clock, settings, metadata, layout, and packaging tests.

The browser suite includes:

```text
48 general layout checks
192 text on/off layout checks
96 comparisons for enlarged text-off blocks
```

Those cover both binary modes, all eight XENEON EDGE slot sizes, seconds on and off, and minimum/default/maximum layout settings.

There are also checks for midnight rollover, settings updates, XML metadata, browser errors, accidental network requests, and official iCUE CLI validation and packaging.

Again:

Clock.

I made a clock.

## Current state

The current package is version **1.1.2**.

It runs natively in iCUE 5.47 or newer, supports the XENEON EDGE's landscape and portrait layouts, works offline, and can be customized enough that I can either make it readable or remove all of the helpful text and force myself to actually read binary.

Naturally, I prefer the second option.

Because displaying `18:42` would have been far too easy.
