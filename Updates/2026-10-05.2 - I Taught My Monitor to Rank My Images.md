# I Taught My Monitor to Rank My Images

I have been making widgets for the CORSAIR XENEON EDGE, because apparently giving me a weird little touchscreen strip is enough to start another software project.

I already had a binary clock.

Then I made this.

**iCUE Image Ranker** is a native iCUE widget that shows me two local images or videos and makes me choose which one I like better.

The winner gets Elo.

The loser gets shame.

[GitHub: ToastSweat/icue-image-ranker](https://github.com/ToastSweat/icue-image-ranker)

And yes, this was designed to work alongside my `r34-tag-watcher`.

Apparently downloading and organizing the archive was not enough. Now the archive needs competitive ranking.

## Two images enter

The basic idea is stupidly simple.

Two media items stay on the XENEON EDGE until I tap the one I prefer. That vote is saved, the ratings are updated, and another pair appears.

Underneath that very scientific process is an Elo rating system. Everything starts at `1000`, with an update factor of `32`.

The selection logic does not just keep throwing the current champions at each other either. It mixes stronger contenders with less-rated media so new stuff still gets a chance to fight its way upward.

There is also a **Top 5** view showing the highest-rated stuff I have actually voted on.

That distinction matters.

It is not claiming it has somehow found the five objectively best files hiding inside a giant archive. It only knows what I have judged so far.

So the Top 5 is less “definitive scientific truth” and more “current results from the world's dumbest ongoing election.”

Votes live in a local SQLite database, and even the current unanswered pair is persisted. If the companion app restarts, it does not quietly reshuffle the question because I escaped judgment by rebooting Windows.

Nice try.

## It leaves the archive alone

One thing I specifically did **not** want was another program screwing around with the source files.

The ranker points at an existing media folder using `archive_root`, scans it periodically, and treats it as read-only.

It does not rename, move, resize, or delete the originals.

The integration with `r34-tag-watcher` is intentionally boring: **files**.

No shared database. No special API between the two projects. No weird dependency where one has to know how the other works internally.

The watcher downloads and organizes files.

The ranker notices completed files and ranks them.

That also means the Image Ranker works perfectly fine against some completely unrelated local media folder.

Tag-organized directories and NTFS hard links are supported too. Hard-linked copies of the same file can share one ranking identity instead of pretending they are different images just because they appear under different tags.

Incomplete `.part` files and recently changing downloads are ignored until they have settled, because ranking half a JPEG would be ambitious even for me.

## Images were easy. Naturally I added video.

The widget also supports MP4 and WebM.

Videos are always muted, loop by default, and can appear both in comparisons and in the Top 5.

Large images are not shoved wholesale at the little display either. The companion uses streaming previews for oversized images, and FFmpeg can generate a real first-frame fallback when a video codec will not play directly inside iCUE.

The source media stays untouched through all of this.

There are also native iCUE controls for things like:

- visibility schedules;
- hiding or showing media;
- text and filename visibility;
- button size;
- contain vs. cover;
- background transparency;
- video playback and looping.

Both portrait and landscape widget layouts are supported.

Which means I have now spent a completely reasonable amount of effort making sure my tiny monitor can rank questionable media elegantly in eight different slot sizes.

## The little local companion

The iCUE widget itself talks to a small local companion application.

The rough shape is:

```text
Media archive
     ↓
Periodic scanner
     ↓
Local companion
  ├── previews / video streaming
  ├── Elo + pair selection
  └── SQLite rankings
     ↓
127.0.0.1
     ↓
iCUE Image Ranker
     ↓
tap winner
     ↓
vote saved locally
```

The server binds only to `127.0.0.1`, media requests and votes are authenticated, and there is no media deletion endpoint.

The rankings database lives locally at:

```text
data/rankings.sqlite3
```

There is also an authenticated read-only export endpoint for dumping rankings and vote history as JSON.

One slightly important packaging detail: the generated `.icuewidget` contains the local installation's API key.

So I do **not** publish prebuilt widget packages.

The public GitHub repository contains the source code and safe templates. Each installation generates its own key and builds its own private widget package.

That keeps the repo useful without accidentally turning GitHub Releases into an API-key distribution service.

## Current state

The project is built for 64-bit Windows with a XENEON EDGE and iCUE 5.47 or newer. The companion uses Python, with Node/npm handling setup, validation, testing, and packaging. FFmpeg/ffprobe handle the video side of things.

The test suite covers things I absolutely would have forgotten otherwise: persistence, hard links, large-image previews, authenticated video streaming, schedule behavior, muted playback, display settings, the different EDGE slot sizes, and keeping private build data out of the public templates.

So now the weird little screen on my desk does more than show information.

It is quietly building a statistical model of my taste, one tap at a time.

Progress.
