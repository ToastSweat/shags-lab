Safe Cracker Is Live!

Holy shit.

Safe Cracker is officially a verified Discord Activity and it is live.

That sentence feels way more significant than it probably should, but this little game turned into one hell of a project.

The idea itself is stupid simple.

Every day there is one four-digit safe combination from 0000-9999. Everyone gets the same safe. You make a guess, the game tells you HIGHER or LOWER, and you keep going until you crack it.

Fewest guesses wins. Time breaks the tie.

That's it.

I wanted something simple that everyone in PGN could jump into once a day, talk shit about their scores, build streaks, and move on with their lives.

Naturally, I somehow turned that into authentication, persistent player data, leaderboards, streaks, Discord Rich Presence, share cards, a dedicated production server, database encryption, privacy policies, Terms of Service, legal research, and identity verification.

You know.

Normal four-digit number game stuff.

The important part is that **Phase 1 is finally done.**

Safe Cracker has been running for a while now on my Windows server behind `safecracker.helvete.pizza`, but Discord Activities have a limitation while you're developing them. Once you want the Activity to work in a larger server like PGN, Discord wants the application properly verified.

Fair enough.

I figured this would mostly be filling out some forms.

It was not mostly filling out some forms.

The verification process wanted a real Privacy Policy and Terms of Service, which immediately forced me to stop and actually think about what Safe Cracker stores.

Luckily, not much.

The game knows your Discord ID, username, display name and avatar so it knows who you are. It stores your completed daily runs so it can calculate scores and streaks. It keeps a session so you don't have to authenticate from scratch constantly.

That's basically it.

No ads.

No purchases.

No selling data.

No weird tracking business.

Just enough information to know that Shagwrath took 8 guesses and 19.56 seconds to crack today's safe and therefore deserves to be insufferable about being rank #1.

Still, Discord requires stored Discord API data to be encrypted at rest.

That sent me directly down another rabbit hole.

Safe Cracker was using Node's built-in SQLite implementation. Nice and simple. One little database file on the server.

Except it was plaintext.

My OVH dedicated server also wasn't using disk encryption, and because it's a remote Windows server with a bunch of other PGN stuff living on it, I absolutely did not want to casually turn on BitLocker and find out what happens after the next unattended reboot.

That sounds like the opening paragraph of a very different blog post.

So instead, I encrypted Safe Cracker itself.

I replaced Node's normal SQLite connection with an encrypted SQLite implementation using ChaCha20.

That part was surprisingly painless.

The more interesting problem was:

Where the hell do you put the encryption key?

Putting an encrypted database right next to a plaintext password that unlocks it is technically better than nothing, but also kind of defeats the spirit of the exercise.

The server doesn't have a TPM, so I ended up using Windows DPAPI.

The production database key is protected by Windows using machine-scoped encryption, stored separately from the game, and the Safe Cracker Scheduled Task can recover it automatically while running as `SYSTEM`.

That means the server can restart by itself and Safe Cracker comes back online without me sitting there entering a password.

I also have an offline recovery copy of the actual database key stored separately, because learning that your database is extremely secure after reinstalling Windows would be a pretty shitty way to discover that you can never open it again.

Then came the migration.

I was not about to test encryption by pointing some new code directly at the live player database and hoping for the best.

So I made backups.

Then I made backups of the backups.

Then I encrypted the backups.

Then I copied an encrypted recovery archive off the server.

Then I compared SHA-256 hashes to make sure that copy was actually identical.

Then I ran a complete migration rehearsal against a copy of the real production database.

Player count before: 1.

Player count after: 1.

Sessions before: 1.

Sessions after: 1.

Daily runs before: 4.

Daily runs after: 4.

The script hashed the contents of every table before and after encryption too.

Everything matched.

Correct key opened the database.

Wrong key got rejected.

Perfect.

Only then did I shut the live game down and do the real migration.

And somehow, after being absurdly careful about the database for hours, the thing that actually broke production was...

A missing newline in `.env`.

Of course it was.

I added the new database-key setting to the production environment file and it got glued directly onto the end of my Discord client secret.

So when Safe Cracker came back online, the health check worked, but Discord authentication failed and anything that touched the database threw a 500 error.

That was a fun few minutes.

Once I noticed what had happened and split the two settings onto separate lines, everything immediately started behaving normally again.

Discord authenticated me.

My existing session worked.

The encrypted database opened.

Stats survived.

The leaderboard survived.

Streaks survived.

Then I cracked Safe #022 in 8 guesses and 19.56 seconds, hit the Share button, and Discord posted the finished Safe Cracker card directly into chat.

Rank #1.

Two-day streak.

And a big fat **Play** button for everyone else.

That was the moment.

Safe Cracker was working end-to-end in production with the encrypted database, Discord authentication, score tracking, streaks, leaderboards and native Discord sharing.

Then I went back to the Developer Portal, finished the Privacy Policy and Terms of Service, did Discord's identity verification, and got the confetti.

Verified.

Live.

Done.

Well.

"Done."

There is already an entire Phase 2 sitting in the corner glaring at me.

I have a much more elaborate visual redesign mocked up in Photoshop with neon chrome, a giant safe interface, custom loading screens, better stats pages, sound, more personality, and probably a ridiculous Photoshop-to-Svelte export tool because apparently I am incapable of simply drawing a UI and then manually recreating it like a normal person.

But I'm putting a pin in all of that.

That was becoming the kind of project where the finish line keeps moving because every cool idea creates three more cool ideas.

Phase 1 needed to ship.

So it shipped.

The game works.

The clan can play it.

There is one safe every day.

Everybody gets the same combination.

And now when someone beats my score I can be annoyed about it using properly encrypted personal data.

Worth it.

**Next:** Let PGN actually play the damn thing for a while.

Phase 2 can wait.
